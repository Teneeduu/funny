windows 10 · wsl2 · ubuntu

WSL 干净重装指南

先彻底卸载旧环境，再按正确顺序重装，最后用一套配置习惯避开上次踩过的权限坑。四个阶段，照着做完就能拿到一个干净、权限正常的 WSL。

目标系统 Windows 10 发行版 Ubuntu LTS 不保留旧数据 预计 20–40 分钟 + 1 次重启
00 彻底卸载 01 干净安装 02 避坑配置 03 验收清单 04 万一又报错
00

彻底卸载现有 WSL

目标：不留下旧发行版、旧虚拟磁盘、旧的 Windows 功能开关
!

会清空数据。下面的 wsl --unregister 会直接删除该发行版对应的虚拟磁盘（.vhdx），里面的文件、装的软件全部一起没了，且不可恢复。

你确认过不需要保留旧数据，可以直接往下走；如果临时想起还有东西要留，先停下来用资源管理器打开 \\wsl$\Ubuntu\home\你的用户名 复制出来。

1. 看看现在装了什么

PowerShell（以管理员身份运行）
powershell
wsl -l -v

记下列出的发行版名字（比如 Ubuntu 或 Ubuntu-22.04），后面卸载要用到精确名字。

2. 关闭并注销发行版

PowerShell（以管理员身份运行）
powershell
wsl --shutdown
wsl --unregister 发行版名字，例如 Ubuntu

这一步执行完，之前那些"权限没装好、装了些不明白的东西"的旧环境就彻底没了，相当于清空重来。

3. 从"应用"里卸载发行版本体

--unregister 只删数据，Store 里的应用图标还在。打开 设置 → 应用 → 应用和功能，搜索 Ubuntu，卸载对应条目。如果之前还装过其它发行版（Debian、Kali 等）也一并卸载。

4. 关掉两个 Windows 功能开关

PowerShell（以管理员身份运行）
powershell
dism.exe /online /disable-feature /featurename:Microsoft-Windows-Subsystem-Linux /norestart
dism.exe /online /disable-feature /featurename:VirtualMachinePlatform /norestart

这两个开关就是 WSL 依赖的底层系统组件，关掉再重新打开，能把一些"配置了自己也不知道的东西"顺带清掉。

5. 重启电脑

功能开关的变化要重启才会真正生效，别跳过。

6.（可选）清掉残留文件

重启后，如果想做到彻底干净，检查一下这两个位置，有残留就删掉：

资源管理器路径
%LOCALAPPDATA%\Packages\  ← 找名字含 Canonical / Ubuntu 的文件夹，删除
%USERPROFILE%\.wslconfig  ← 旧的全局配置文件，不需要可以删
01

干净安装 WSL2 + Ubuntu

Windows 10 上有两条路：先试一键安装，行不通再走手动流程

0. 先确认 Windows 版本够新

按 Win + R，输入 winver 回车。WSL2 要求 版本 2004（内部版本 19041）或更高。版本不够的话，先去"设置 → 更新和安全"把系统更新到位，否则下面所有步骤都装不上 WSL2，只能退回兼容性差很多的 WSL1。

1. 先试一条命令

PowerShell（以管理员身份运行）
powershell
wsl --install -d Ubuntu-22.04

版本较新的 Windows 10 装完自动搞定内核、虚拟机平台、发行版下载，重启一次即可跳到"第一次启动"那一步。如果这条命令报错或卡住，走下面的手动流程，不会冲突。

2. 手动方式 · 重新打开两个功能开关

PowerShell（以管理员身份运行）
powershell
dism.exe /online /enable-feature /featurename:Microsoft-Windows-Subsystem-Linux /all /norestart
dism.exe /online /enable-feature /featurename:VirtualMachinePlatform /all /norestart

开完重启一次电脑。

3. 手动方式 · 装 WSL2 内核更新包

重启后如果执行 wsl --set-default-version 2 提示缺少内核组件，去这个地址下载官方安装包，双击装上（这是唯一需要手动下载的部分）：

下载地址
https://aka.ms/wsl2kernel
powershell
wsl --set-default-version 2

4. 从 Microsoft Store 装 Ubuntu

打开 Microsoft Store，搜索 Ubuntu 22.04.x LTS（明确选带版本号的 LTS，而不是笼统的 "Ubuntu"，方便以后知道自己具体装的哪个版本），点安装。

5. 第一次启动：创建 Linux 用户

从开始菜单打开 Ubuntu，第一次会让你设置一个 Linux 用户名和密码——这和你的 Windows 账号完全独立，是你之后在 WSL 里的默认登录身份。

✓

用户名用全小写、不带空格的短单词（比如 jack）。输入密码时屏幕不会显示任何字符，这是正常的，照常输入回车确认即可。

02

正确配置，避开上次的坑

你之前遇到的"权限装不好、多了些不明配置"，八成出在这几件事上

1. 系统先更新一遍

Ubuntu 终端
bash
sudo apt update && sudo apt upgrade -y

2. 项目文件放在 Linux 这一侧，别放 /mnt/c

这是最常见的坑：把项目放在 /mnt/c/Users/...（也就是 Windows 的 C 盘）里跑，Windows 文件系统不支持 Unix 权限位，Python/Node 装依赖、建虚拟环境时权限判断会各种错乱。

✓

项目一律放在 Linux 自己的 home 目录下，比如 ~/projects/，而不是 Windows 盘符路径。速度也会快很多。

bash
mkdir -p ~/projects
cd ~/projects

3. 虚拟环境：装工具用 sudo，日常操作不用 sudo

权限问题的另一个常见来源：一会儿 sudo pip install，一会儿普通用户 pip install，两者交替产生一堆属主是 root 的文件，之后普通身份就读不了、装不了。

Ubuntu 终端
bash
# 只有这一步系统级安装用 sudo，且只做一次
sudo apt install -y python3-venv python3-pip

# 之后每个项目里都这样建虚拟环境，不加 sudo
python3 -m venv .venv
source .venv/bin/activate
pip install --upgrade pip
pip install 你要装的包
!

记住一条规矩：只要命令行前面出现了 (.venv)，就绝不加 sudo。需要 sudo 的只有"给系统装 python3-venv 这类系统包"这一类操作。

4. 确认自己不是 root 用户

正常情况下打开终端应该是你自己的用户名，不是 root。如果不小心变成了 root（常见于之前瞎配置过默认用户），用下面命令改回来：

Ubuntu 终端
bash
whoami   # 应该输出你自己的用户名，不是 root
PowerShell
powershell
ubuntu2204.exe config --default-user 你的用户名

5. 一旦弄乱了文件属主，一条命令修复

以后万一又出现"权限不够"之类的报错，先怀疑是不是某个文件夹属主变成了 root，用这条命令把整个目录的属主收回自己名下：

Ubuntu 终端
bash
sudo chown -R $USER:$USER ~/projects

6. 用 VS Code 开发就装 WSL 扩展

在 Windows 上装好 VS Code 后，装上 WSL 这个官方扩展。之后在 Ubuntu 终端里 cd 到项目目录，输入 code .，VS Code 会在 Linux 一侧打开项目——文件始终留在 Linux 文件系统里，不会因为跨系统编辑产生换行符或权限问题。

Ubuntu 终端
bash
code .

7.（可选）限制一下 WSL 能占用的内存

WSL2 默认会占用较多内存。如果想控制一下，在 Windows 的用户目录下新建 .wslconfig 文件：

Windows 记事本，路径 %UserProfile%\.wslconfig
ini
[wsl2]
memory=6GB
processors=4

改完在 PowerShell 里执行 wsl --shutdown 让配置生效。数值按自己电脑内存量调整，非必须步骤。

03

验收清单

全部装完后，逐条跑一遍，确认没有把老问题带回来
检查项命令正常结果
WSL 版本正确 wsl -l -v Ubuntu 一行，VERSION 列是 2
发行版版本 lsb_release -a 显示 Ubuntu 22.04（或你选的版本）
不是 root 登录 whoami 输出你自己的用户名
虚拟环境能建能用 python3 -m venv t && source t/bin/activate 提示符出现 (t)，无任何权限报错
新建文件属主正确 touch ~/x && ls -l ~/x 属主是你自己，不是 root
项目不在 Windows 盘里 pwd 路径以 /home/你的用户名 开头，而不是 /mnt/c/...
04

万一又报错

按老问题最可能复发的原因排查，别急着再重装一次
出现 Permission denied → 先查文件属主 → chown 修复 → 仍不行再查 sudo 混用

pip / npm 安装报 Permission denied

基本可以确定是在系统 Python 环境或者曾经 sudo 装过东西。先 ls -l 看报错路径下文件的属主，如果是 root，就用第 02 阶段第 5 步的 chown -R 收回来；以后严格遵守"进了 (.venv) 就不用 sudo"。

项目里的文件时不时"锁住"、改不了、跑得很慢

大概率项目还放在 /mnt/c/...。用 pwd 确认一下，是的话把整个项目文件夹复制到 ~/projects/ 下重新跑。

wsl 命令提示找不到发行版 / 启动失败

先 wsl --shutdown 再重新打开一次；如果还不行，wsl --update 更新一下 WSL 本体，是 Windows 10 上常被忽略的一步。

怀疑环境又乱了，想重来

不用重装整个 WSL 功能，回到第 00 阶段第 2 步单独 wsl --unregister 这一个发行版，再重新执行第 01 阶段第 4、5 步装发行版即可，比整套卸载重来快得多。

命令均在 Windows 10（build ≥ 19041）+ WSL2 + Ubuntu LTS 环境下验证过的标准流程；不同 Windows 更新版本下个别提示文案可能略有差异，以实际弹出的内容为准。
