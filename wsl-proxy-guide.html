wsl2 · nat 网络 · clash / v2ray

WSL 联网代理配置

Windows 上开着 Clash / V2ray 这类代理时，WSL2 不会自动跟着走代理，遇到 apt update 报 DNS 解析失败多半是这个原因。这份指南记录怎么让 WSL 里的命令行工具乃至 apt 都吃到 Windows 那边的代理。

00

为什么 WSL 不会自动走 Windows 的代理

两边是两套独立的网络栈，不共享"系统代理"设置

Clash / V2ray 在 Windows 上开启后，一般是改 Windows 的"系统代理"设置，或者监听 127.0.0.1 的某个端口。这两者 WSL2 都摸不到——WSL2 走的是自己独立的虚拟网卡（NAT 模式），既不读 Windows 注册表里的系统代理配置，也没法通过 127.0.0.1 连到 Windows（WSL 里的 127.0.0.1 是它自己的回环地址，跟 Windows 的是两个东西）。

WSL 里的程序curl / apt / git
──✕──
WindowsClash :7890

所以想让 WSL 也走代理，得做两件事：让代理监听 WSL 摸得到的地址，再让 WSL 里的程序知道往哪儿发请求。下面 01~04 步就是干这个的。

01

代理软件里打开"允许局域网连接"

默认只监听 127.0.0.1，WSL 连不上，得让它对外监听

Clash 系客户端

Windows · Clash 设置界面

打开 Allow LAN（允许局域网连接）开关，记下混合端口 / HTTP 端口（默认常见是 7890）。V2rayN 之类的客户端找"允许来自局域网的连接"这一项，效果一样。

开这个开关之后，理论上局域网里其它设备也能用你这个代理，如果不放心可以在 Windows 防火墙里把这个端口限制成只允许 WSL 的网段访问，不是必须但更严谨。

02

从 WSL 里拿到 Windows 主机地址

这个地址就是接下来代理配置里要用的"服务器地址"

查默认网关

Ubuntu 终端
bash
ip route | grep default | awk '{print $3}'

WSL2 是 NAT 网络，这个默认网关地址就是 Windows 主机在 WSL 这个虚拟网络里对应的 IP，用它来访问跑在 Windows 上的代理。如果之前手动把 /etc/resolv.conf 写死过（比如改成 8.8.8.8），跟这一步没关系，两者互不影响。

03

让命令行工具走代理

curl / wget / git / pip / npm 这些都认标准代理环境变量

写进 .bashrc，一劳永逸

Ubuntu 终端
bash
echo '
export WSL_HOST=$(ip route | grep default | awk "{print \$3}")
export http_proxy="http://$WSL_HOST:7890"
export https_proxy="http://$WSL_HOST:7890"
export all_proxy="socks5://$WSL_HOST:7890"
' >> ~/.bashrc
source ~/.bashrc
echo $http_proxy

7890 换成你代理软件实际监听的端口。写进 .bashrc 之后每次开新终端会自动生效；source 是让当前这个终端立刻生效，不用关掉重开。

✓

配完用 curl -I https://www.google.com 测一下，能返回 HTTP 状态码就说明这层通了。

04

单独给 apt 配代理

apt 不读 http_proxy 这些环境变量，得走自己的配置文件

写一个 apt 代理配置

Ubuntu 终端
bash
echo "Acquire::http::Proxy \"http://$WSL_HOST:7890\";
Acquire::https::Proxy \"http://$WSL_HOST:7890\";" | sudo tee /etc/apt/apt.conf.d/proxy.conf

要求前面第 03 步已经在当前终端里 export 过 $WSL_HOST，否则这里会写成空值。写完再跑 sudo apt update，能正常拉到索引就是配对了。

05

如果代理是 TUN 模式，前面都配了还是不通

TUN（全局虚拟网卡）模式会接管全系统流量，容易把 WSL 的网段一起吞掉

先定位是不是这个原因

临时把 Clash / V2ray 切回"系统代理"模式（不是 TUN/虚拟网卡模式），再测一次网络。如果切回去就通了，说明问题出在 TUN 模式接管了 WSL 的虚拟网段但没放行。

解决：把 WSL 网段加入直连 / 放行规则

先查 WSL 自己的网段
bash
ip addr show eth0 | grep inet

拿到类似 172.x.x.x/20 这样的网段后，去 Clash / V2ray 的"规则"或"路由"设置里，把这个网段加进"直连"或"绕过代理"列表——注意是让 TUN 驱动放行这个网段的流量能正常出网，而不是让它绕开代理直连外网（那样又变回最初不通的状态），具体选项名称因客户端而异，找"Bypass"/"直连"/"排除"这类字眼。

06

验收清单

换了新代理软件、新电脑，或者重装 WSL 之后，照这个走一遍
检查项命令正常结果
拿到主机地址echo $WSL_HOST输出一个 IP，不为空
命令行代理生效curl -I https://www.google.com返回 HTTP/2 200 之类的状态行
apt 代理生效sudo apt update正常拉取索引，无 Temporary failure
DNS 正常cat /etc/resolv.conf有一行 nameserver，指向可用地址
这份配置是"当前终端会话 + 这个用户"级别的，重装 WSL 发行版之后 .bashrc 和 apt 配置会一起清空，需要重新走一遍 01~04；只是关掉重开电脑、代理软件重启，不影响。
